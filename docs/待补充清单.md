**2026-10-15 追加修复的三个坑（都是实测踩出来的）**

1. **API 的启动上下文决定它能不能拉 GUI**：从受限会话启动的 API，`Start-Process chrome.exe`
   会静默失败（现象：脚本报 `launched=true`，但 20 秒内 6901 不通、进程列表里没有 Chrome）。
   现在失败时会直接给出病因（"API 进程没有桌面权限，请在自己的 PowerShell 里重启 API"），
   审计也不再无脑写 "ok"，而是记每一步的真实结果。
2. **「停止监听」一直没生效却报成功**：监听启停走冻结脚本 `tools/qianniu/start-im.ps1`，
   它含中文字面量且无 UTF-8 BOM，`powershell.exe`(5.1) 按 GBK 读会整脚本解析失败
   （exit_code=1），而代码不看退出码。→ 新增纯 ASCII 的 `deploy/monitor-control.ps1`
   负责停止/状态，启动改由 Python 直接拉起 node，接口失败会真的抛错。
3. **「启动监听」接口超时但监听其实起来了**：`Start-Process` 起的 node 继承了 PowerShell 的
   stdout 管道，Python 的 `communicate()` 等不到 EOF。→ 由 Python 直接 spawn，句柄继承可控。

另外 `deploy/start-native.ps1` 补了 UTF-8 BOM，这样 Windows PowerShell 5.1 也能跑
（`start-im.ps1` 是冻结源码不能动，只能用 pwsh 7 跑）。

**2026-10-15 追加：启动策略改成"先清端口再起"**（业务要求）

**判定口径（重点：不只看 cookie）**

1. **会员 cookie**：`unb` / `aui` / `cnaui` / `_nk_` / `tracknick` / `__cn_logon_id__` 里至少有一个
   "解出来非空"。登录页残留的 `lid` / `lgc`（未登录时也会有空值）只用来解释，不作判据。
2. **服务端探测**：带着浏览器里的 cookie 请求一次 `work.1688.com/home/page/index.htm`，
   最终 URL 落在登录页 → 判未登录。这一步不依赖任何标签页。
3. **页面证据**：浏览器里有标签页被重定向到登录页 → 判未登录。
4. **聊天页可读性**（点「立即体检」时）：能读到 `__QN.core()` 且会话列表可读 → 登录态有效。

> 实测踩到的坑：这台机器 6901 端口的调试实例**早已掉线**（标签页停在 login.taobao.com），
> 但 cookie 里还留着 `lid=playworld152:it`。只按"cookie 在不在"判会显示成"已登录、一切正常"，
> 正是这一条想消灭的"静默失效"。

**为什么要补**：现在 `/api/system/health` 的 `cdp` 只判「Chrome 调试端口通不通」，
**完全不看 1688 是否还登录着**。Chrome 起在那里、端口通、六项全绿，但账号已经掉线时，
仪表盘看着一切正常，实际所有业务动作都做不了——2026-10-08 关掉浏览器那次就是这种
「静默失效 45 小时、面板全绿」的情况。

## 3. ⬜ 「0 家联系成功」不许再报成功

**为什么要补**：`contacted == 0` 时作业仍然会被判为 `done`。
如果结果页是之前留下的标签、DOM 里还挂着商品卡，流程会逐个去开聊天窗
（开出来的是登录页）→ 每家短语发送超时 → 最后返回 `opened: 0`，
**全程不抛异常**。于是界面显示"成功"，全自动流程还会继续往下走，
并往飞书推一张空比价表——比直接失败更误导。

**改哪里**

- `Automatic_Inquiry_System/backend/app/handlers.py` 的 `_campaign_launch`
  （约 14-16 行）：现在直接 `return await bridge.call("campaign.launch", ...)`，
  对返回值不做任何校验。
- bridge 返回的是 `{imageId, contacted}`，来自
  `tools/qianniu/blocks/campaign.mjs` 的 `launchCampaign` 结尾
  `return { imageId: r.imageId, contacted: c.opened }`。
- 建议：`yes=true` 且 `contacted == 0` 时抛错（或返回里带 `warning`），
  并让 `campaign.fullauto` 因此中止、**不推空比价表**。
  ⚠️ 注意区分 `yes=false` 的演练（演练 0 家是正常的，不算失败）。

**怎么算做完**：在未登录 / 结果页无卡片的场景下点一次「启动」，
作业应显示失败或明显告警，而不是 `done`；飞书不应收到空比价表。
